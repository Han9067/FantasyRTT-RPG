# Project conventions

- Current local Windows release: 0.0.3 (based on web 0.0.35). Increment only the patch once per delivered game update. Never change the first two components unless asked.
- Validate local playable changes and export Windows Desktop to ../PlayTest/FantasyRTT-RPG.exe. The historical Web preset remains available. After each completed version, commit the validated project changes on main, push to origin/main on GitHub, and verify the remote commit.
- The visual source of truth is the purchased user-supplied MedievalFantasyCharacters.zip. Read docs/character-design.md before changing characters.
- Preserve loose source PNGs in art/medieval (.gdignore). Build assets/medieval atlases/catalog with tools/build_medieval_atlas.py; do not hand-edit generated images. Runtime uses only needed parts. Preserve original RGBA; no AI redraws, recolouring or resampling.
- The creator has personal details only at the top, and a portrait on the lower left with two columns of part selectors without scrolling (beard/beard color/weapon at upper right) on the right. Gender is independent of appearance. Creator is human-only; hats/gloves/race have no selectors. Bare hands follow skin. Select primary type/item from melee except shields, then secondary type/item from one-handed melee including shields. Shields draw over the offhand. Other secondary weapons draw beneath its grip. Two-handed primary items clear and disable secondary equipment. Keep headgear/glove source assets for future equipment; mounts remain excluded.
- Compose 128x96 frames at integer coordinates; preserve the original 80x56 starter preview crop/scale, expand one shared crop only for larger equipment. Idle/walk/run have 4/8/8 frames; attack has 6 frames at 10fps, matching the weapon-specific chop_attack_sample.gif or thrust_attack_sample.gif with fixed body/head and no extra recovery pause. spear is thrust_attack; every other held weapon uses chop_attack. Preview controls are idle/walk/attack; respect per-frame durations. Head/accessory offsets follow the body. Use nearest filtering. World/battle feet are the unit position.
- Legacy assets/characters, assets/adventurers, tests/fixtures, and tools/references were explicitly removed by the user. Do not restore them.
- Character creation enters WorldMap. WorldMap extends BattleMap movement/camera but is always selected, ignores left-click selection, and uses the exact user-uploaded 2560x1280 Tiled map (80x40 tiles), with four native 96x96 cities numbered 1..4 (two <=2048px terrain chunks and a 1024x512 minimap). World camera speed is 840 screen px/s (2x battle), supports arrows and WASD, and the minimap viewport rectangle can be dragged with a stable grab offset, clamped edges and no party orders. Use art/world/tiled/WorldMap.tmx as the current editable terrain/city source; no procedural replacement layouts or old city names. Read docs/world/world-prototype.md for geography references and prototype limitations. The centered top button enters BattleMap; its return button restores world position/camera/zoom. Do not change battle mechanics while working on the campaign prototype. Battle uses a fixed 2560x1600 world, a bounded Camera2D with WASD pan and cursor-anchored wheel zoom 1x..3x, and a CanvasLayer HUD. Sprite scale stays 1; minimum camera zoom shows native pixels. Keep nearest filtering, central spawn, click/four-direction box selection, selection-gated right-click walk orders and idle on arrival. All pointer positions must pass through the camera canvas transform; HUD hit areas remain in screen coordinates. UI screens restore canvas_items scaling. Terrain is a static procedurally baked texture with deeper green grass and no stone decorations; do not regenerate it on camera movement, zoom or window resizing.
- Run meaningful smoke checks for source integrity, selector boundaries/dependencies, layout, preview animations, and world continuity, run tests/world_smoke.gd for campaign transitions/persistent selection/camera bounds and tests/battle_smoke.gd for selection/movement/camera bounds/zoom/HUD checks, then verify the web UI in a browser before publishing. Verify the matching GitHub Pages Actions deployment succeeds before reporting the site ready; GitHub web Actions pages work when the API/site are blocked. Share the full game URL, not a renamed link.

- Current source tree contains 4,497 files. The weapons subtree has 330 PNGs. Use Desktop/MedievalFantasyCharacters/sprites/weapons as the local weapon source. Windows 0.0.3 syncs its one_shield folder (48 shields). Numbered filenames replace __rNN_cNN. Full ZIP imports validate in staging and replace old trees; never merge removed files back. Guides live only in art/medieval/Animation Guide.

- docs/weapons/weapon-name-proposals-ko.txt and .csv are review-only name proposals for 109 equipment appearances, excluding shield/polearm/ammunition; sling animation frames are aliases, not separate weapons. Do not apply proposed names or stats to gameplay without a request.

- Active campaign source (0.0.33): art/world/tiled uses the uploaded MedievalMap.zip with the city artwork updated from Desktop/MedievalMap for Windows 0.0.2. Preserve every visual tile layer, order, source PNG, TSX and map dimension exactly. The City layer has four copies of the user's replacement 3x3 (96px) city tile, not the old 42-city design. Preserve the supplied River/Road/Forest/Mountains/Ect content including blank grass. Only hidden GameObjects was added: City rectangles 1..4 and PlayerSpawn at (1408,672). Do not introduce gameplay interactions without a request. Read actual TMX dimensions; the inherited Layout text/README_KO refer to an older map and are not authoritative.
- tools/build_world_map.py validates render-manifest.json, derives dimensions and GameObjects metadata, splits the original full-size Tiled render into native chunks (<=2048), deletes obsolete chunks and writes an aspect-correct minimap. Normal builds need Pillow; after deliberate TMX/TSX/PNG edits run --refresh-render with TILED_RASTERIZER and its normal library environment. Runtime reads map bounds/spawn from world_layout.json; the minimap fits the map aspect ratio. Tests compare all rendered pixels against Review/WorldMap_uploaded.png and every original layer/asset against upload-manifest.json, then check native city pixels, camera/minimap/transition behaviour. The uploaded TMX snapshot in Review is for provenance, not the editable project entry point.
- art/world/resources, art/world/tiles, the older traced plan and tools/world_tiles.py are historical references only, excluded from runtime by art/world/.gdignore. Do not restore their old procedural terrain or 128px city sprites to the live map.

- World party presentation (0.0.33): WorldPartyMarker is a native 32x32 token centered at unit_position. Preserve assets/world/party/wObj1.png and wObj2.png from the latest Desktop.zip (2026-11-10 update). Draw original white wObj2, the selected character clipped with the FULL original wObj2 alpha (including partially transparent edge pixels), then original wObj1. Never tint, rescale, dilate or reshape either source image or inset the mask. The world portrait is ONLY unarmed idle frame 0, composed from a copy of the chosen appearance with include_weapon=false, in its own single-frame SpriteFrames; no playback or direction flipping during any travel/return. Never mutate the shared battle/creator frames. Keep native 1x pixels. The marker replaces world ground shadow/selection ellipse.

- World navigation (Windows 0.0.1): tools/world_navigation.py derives conservative 8px water and 16px mountain cells from original water-palette, rock silhouette, road dirt and opaque bridge masks. Keep actual water blocked beside/above/below bridge decks; transparent mountain margins are walkable. Combine the masks on a shared 4px grid; preserve safe 4px cells fully on an opaque bridge deck. Bridge object local ID10 replaces the road opening in its cell; translucent shadows never open water. Mountains always win. No visual source changes. WorldNavigation caches AStarGrid2D/components; no-corner-cut diagonals and DDA path simplification; cursor and orders share this mask. First entry zoom3 with centered player; saved travel restores its own zoom/camera. Run navigation/world/battle and browser checks.
